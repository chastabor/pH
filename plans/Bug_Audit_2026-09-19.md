# Bug audit, 2026-09-19 — findings and a plan to fix them

*A read of every shipped package for defects, and the order to repair them in.*

## How this was done

The seven packages (about 84 000 lines under `packages/*/src`) were read in ten
areas, each with CodeGraph for callers and blast radius and with scratch scripts
where a reproduction was cheap. Every finding below is marked **confirmed**
(reproduced, or the code path is unambiguous) or **plausible** (traced, not run).
Ruff and mypy pass on the tree; the full suite passes outside the sandbox
(2933 passed, 8 skipped), so nothing here is a regression the gates already see.
Citations are file and symbol, per §9 of `DESIGN.md`. Gaps already listed in
`DESIGN.md` §8 are not repeated.

The reproductions live in the session scratch directory; each one that matters is
turned into a named test in the plan, because a finding without a test that fails is
the kind of claim this codebase does not keep.

## Summary

| severity | count | where they cluster |
|---|---|---|
| High | 20 | teardown under cancellation, persistence, the boundary, the daemon, the kernel, the TUI |
| Medium | 39 | classifiers and gates, adapters, the agent loop, workspace bookkeeping, front-end state |
| Low | 42 | edge cases, doc drift, latent footguns |

Four themes account for most of the high-severity list, and each has one root:

1. **Teardown is not cancellation-safe outside `Context.dispose`.** `dispose` shields
   itself; the code *around* it does not. `ph_app.runtime.mounted` awaits `drain()`
   first, `Supervisor._start` is unshielded, `Context.effect` can lose a disposer,
   and a sibling `dispose` runs unshielded when another holds the tree-wide flag.
2. **Two writers, or one writer twice.** The lease locks a path the log is not at;
   overlapping flushes restore out of order; repair re-registers already answered
   calls; a fork whose boundary is an end-seed owns nothing.
3. **The boundary does not mean what it says.** `fs.resolve` never normalizes `..`,
   so the worktree tier's write bound and every `permissions-fs` deny are walked
   around with `public/../secrets`; the `read-only` preset is logged and displayed
   but never handed to a backend.
4. **An error that is recorded as success.** An Anthropic or OpenAI-compatible
   mid-stream error ends as `stop`; a transport error is `UNKNOWN` and never retried;
   `phern -p` exits 0 on an error turn; the retry budget is shared across agents;
   telemetry drops every record that lands while another is exporting.

### Increment 1 — teardown that survives cancellation (A1, A2, A3, A4, A5, A11, E1)

**Landed 2026-09-20.** Seven source changes and twelve tests, each of which
fails without its fix. Four deviations from the sketch below, all deliberate:

* the daemon tests need no socket, because driving `Supervisor.start` directly
  reaches the same code and runs everywhere;
* `Context.dispose`'s per-tree `unwinding` flag became a `ContextVar` rather than
  gaining a second shield, which keeps the measured saving for the nested case it
  was written for;
* **`drain` shields and bounds itself** rather than being wrapped by its caller,
  which is the shape `dispose` already had and the reason `ph.resources` gives
  for it — a shield around a self-shielding callee makes the outer deadline
  inert. `DRAIN_SECONDS` is `GRACE_SECONDS / 2`, and a drain also honors a budget
  `unwind_by` seeded, so a ten-root shutdown spends one total rather than ten;
* **the daemon's mount runs on the supervisor's task group** rather than under a
  shield in `start`. A client that disconnects cancels only its own await, so
  there is no start budget to guess at and no shutdown delay to pay; `_mounting`
  is what keeps two callers to one mount now that no caller holds a lock.

The one-line version: **nothing between a cancellation and `Context.dispose` may await
unshielded.**

1. `ph_app/runtime.py:mounted` — dispose first, then drain, or run both under
   `anyio.CancelScope(shield=True)` with the same `GRACE_SECONDS` deadline `dispose`
   already budgets. Test: `test_runtime.py::test_a_canceled_mount_still_disposes`
   (a detached sleeper, an outside cancel, assert every effect ran).
2. `Context.drain` — `with suppress(Exception, asyncio.CancelledError)` around
   `await task` is not enough in anyio; check `task.cancelled()` before awaiting and
   skip it. Test: `test_cordis_context.py::test_drain_ignores_a_canceled_detached_task`.
3. `Context.effect` — after `await maybe_await(enter())`, if `not self._active`,
   call the disposer immediately and raise. Test:
   `test_cordis_context.py::test_an_effect_acquired_into_a_dead_scope_is_released`.
4. `Context.reconcile` — mark a dependent whose `apply` raised as `failed` (a new
   field `_Dependent.failure`), exclude it from `ready()`, report it through
   `waiting_on`/doctor, and let the loop continue past it. Test:
   `test_cordis_context.py::test_a_row_that_failed_to_apply_does_not_block_the_rest`.
5. `Context.dispose` — make the shield decision per *root of the unwind* rather than
   per runtime: a second concurrent disposer that finds `unwinding` set opens its own
   shielded scope with the same deadline. Test:
   `test_cordis_context.py::test_two_siblings_disposing_at_once_are_both_shielded`.
6. `Supervisor._start` — wrap the body in a shielded scope with a deadline (a root's
   lifetime is the daemon's, not the requester's) and register `self.roots[root_id]`
   only after the last await, or add `exits.callback(lambda: self.roots.pop(root_id, None))`
   before it. Test: `test_daemon_lifetime.py::test_a_client_that_leaves_mid_mount_leaves_no_zombie_root`
   (needs a socket; mark per `test.sh`'s platform list).
7. `OrphanJournal.sweep` — treat a recorded token of `None` exactly like an
   unreadable one: report, never kill. Test:
   `test_orphans.py::test_a_record_with_no_token_is_reported_not_killed`.

### Increment 4 — the kernel under pressure (F1, F2, F3, F4)

**Landed 2026-09-20.** Eight source changes and six tests, each failing without
its fix. Five notes on what was done differently from the sketch:

* **`SIGXCPU` was not moved to `add_signal_handler`, and moving it would have
  been a regression.** A loop callback cannot reach a cell spinning in Python —
  the loop is starved, which is the whole reason the CPU budget exists — so that
  route would have disarmed the budget for its main case while fixing its
  secondary one. The handler stays a raising `signal.signal` handler and now asks
  *where the cell is* before it raises: `_executing_cell` walks the interrupted
  frame's stack for `CELL_FILENAME`, raising when the cell is on it and
  cancelling the run task when it is not. Both routes report `cpu`; they differ
  only in what they are allowed to interrupt. The discrimination is exact rather
  than heuristic — a suspended cell's frame is not on the main thread's stack;
* **the re-delivery is stopped at the source.** `relax_cpu_budget` puts the soft
  limit back to the hard one in the handler, before anything else, so one breach
  is one signal. Raising the limit only in the `except CpuBudgetExceeded` branch
  (the sketch) would still have left the window between the raise and that
  branch, and would have missed the cancel route entirely;
* **`_send_lock` was not bounded.** Bounding the send would abandon a frame
  mid-write and corrupt the channel for a run that might still recover. What
  blocked was the *clock*, not the send: `_watch` awaited a helper that sent
  before it started timing. `_ActiveRun.begin_abort` now claims the clock — first
  caller wins, mirroring `settle` beside it — and the ask follows it, from a task
  in `_watch`'s case and after the reply in `_serve_call`'s. The shutdown send
  *is* bounded, because there the frame is followed by a kill;
* **a closed channel now tears the process down**, not only on an oversized
  frame. The sketch scoped this to the frame cap, but `_pump` reaches
  `_on_closed` by three routes and two of them leave a live child nobody can
  reach: `_alive` is false, so the next run spawns a second process beside the
  first;
* **`PROTOCOL_VERSION` moved to 2**, by the rule its own docstring states: `call`
  gained a *required* field, which a mismatched pairing misreads rather than
  ignores — a guest that does not stamp `run` would have every binding call
  refused as "not available". A warm venv rebuilds, and `boot-ack` refuses a
  pairing that still disagrees. **This incidentally settles I1**: `DESIGN.md` §1
  said the guest declares 2 while it declared 1, and it now declares 2. The
  sentence is true, though for a reason its author did not have.

The stray-call fix is two halves and both are wanted: the guest cancels a
settled run's leftover tasks (the fix — a task that is gone issues nothing), and
the host refuses a `call` stamped with a run that is not open (the backstop, for
a task that survives cancellation). Serving one cost the *next* run's call
budget, dispatch id and approval decision.

Two tests reproduce only as a **hang** without their fix, and say so: a guest
that died of a budget breach is kept alive by the worker thread it could not
interrupt, so the host never sees EOF, and a ladder blocked on `_send_lock`
never reaches the kill. Both run under `anyio.fail_after`.

**Two defects in this increment were found by the cleanup review that followed
it, and fixed there:** the `run` stamp was read from `Runner._run_id` at the
moment the call went out, so a task that survived cancellation relabelled itself
with whichever run was open and the host's refusal never fired — it is a
`ContextVar` now, which `asyncio.create_task` copies, so a task carries the run

### Cancellation became event-driven (2026-09-20)

Not an audit finding — asked during the increment 7 review, on noticing that
`POLL_SECONDS` existed at all. It was never a property of the system: a
`CancelToken` is a flag with an upward `parent` link and a synchronous
`cancel()`, so there was nothing to subscribe to and every waiter had to ask.

`Cancellation` now offers `wait()` and `CancelToken` carries a private
`anyio.Event`. The non-obvious half is the **direction**: cancellation is
inherited upward and `cancel()` sets one node, so an event on the cancelled
token alone would leave every waiter on a *child* asleep — which is the ordinary
case, since a tool's token is a child of the turn's. `wait()` watches the whole
ancestor chain rather than keeping a downward registry of children, which a
long-lived root would grow one entry per tool call and never shrink.

Checked before committing to it: `anyio.Event()` constructs outside a running
loop (tokens are built in sync code) and costs 792 ns; all three `cancel()` call
sites are on the loop, so there is no cross-thread `set()`; `CancelToken` is the
only implementer of `Cancellation`; and tokens are never compared or hashed, so
the field is `compare=False`.

**`POLL_SECONDS` stays, and now means what it says**: the stop ladder's cadence.
`Kernel._watch` asks a second question on the same tick — has the abort grace
expired — and a deadline needs a clock whatever the flag does. The *cooperative*
check inside a tool body (`raise_if_canceled` between steps) is also unchanged:
that is a body asking whether it is still wanted, not a waiter.

Worth being honest about the payoff: the CPU saved is negligible (~20 wakeups a
second per running child), and the latency is 50 ms on a path that then tears
down a process. What it buys is that `ph.cancel` no longer exports a flag you
cannot await.

### Increment 9 — latent footguns and drift (A6–A10, A12, A13, C8–C11, D10–D13, E5, E6, F5–F7, G8, G9, H7, J9, K7–K10, X3, X4, I1)

**Landed 2026-09-20 — 31 of 31, all four gates green at each step.** Every one
is pinned by a test verified to fail without its fix. D10 came last and is
described at the end of this section.

The second batch (F5, F6, F7, G8, H7, J9, K7) turned out to hold the increment's
sharpest items, which is why they were left for last:

* **G8 needed the log to carry the signature.** Anthropic signs every thinking
  block and *refuses a conversation that sends one back without it*, so the
  attestation cannot live in the adapter — a resumed session rebuilds history
  from events, and anything held in memory is gone. `ReasoningBlock` gained
  `signature` and `redacted`. Three defects compounded here: the
  `signature_delta` was read by the text branch and emitted as an empty
  `TextDelta` on a reasoning block, so the signature was discarded; the block
  went back unsigned; the request is refused. `redacted_thinking` was opening as
  a *text* block, putting Anthropic's ciphertext in front of the model as
  something it had said. An unsigned block is now dropped rather than sent — the
  same reading G9 established for the OpenAI wire.
* **F7 was three unrelated defects in one row, and one of them found a bug in
  its own fix.** A run cancelled before its first line ran none of `_execute` —
  not its `try`, not `_settle`, not either fallback the guest carries for exactly
  that promise — so `run`+`cancel` in one read chunk wedged the kernel. The first
  fix sent a terminal frame with no `type`, which the host never pairs; the test
  caught it. It is tested at the *guest* rather than through the kernel, because
  the stop ladder sleeps `POLL_SECONDS` before it looks at the token and the
  window is a guest-level one.
* **F5's marker digests the guest's version, not its source**, so a checkout's
  guest was installed non-editable and kept serving the bytes it had at build
  time through every later edit — the skills beside it had taken `--editable` for
  that argument since they were written. The build also had no cross-process
  lock at all, and `_build` opens with `shutil.rmtree`.
* **K7's `"canceled"` outcome was unreachable.** `_route` checks the token on the
  way *in*, so a cancel arriving while the person is being asked unwound past
  `_record_decided` — and the crash repair then stamps that `interrupted`, which
  is a different and less true story than "somebody pressed escape". Its second
  half: `ask` folds three situations into `None`, and `ask_user` rendered all
  three as "nobody is attending this session" — the harness contradicting a
  person who had just dismissed the prompt, in the direction that tells the model
  to carry on alone. `DECLINED` says the other thing.
* **J9's probe declined on a host where the sandbox works.** `$PH_HOME` under
  `~/Library/Application Support` made the unquoted redirect land elsewhere, so
  `landed` was false and the rung switched itself off with "the sandbox refused a
  write inside the workspace it was given". `--new-session` is the terminal half
  of what `--unshare-pid` already claims — without it a confined command can push
  characters into the person's own shell with `TIOCSTI`.
* **H7's `/compact` froze the whole UI**, awaited on Textual's message pump, two
  lines below the shell branches that already use `run_worker`. And the
  trajectory viewer's `q` was bound under the id `quit`, which `set_keymap`
  rebinds to `ctrl+d` — the ids are a namespace shared across apps, so the only
  documented way out of the viewer was moved to a key its footer does not
  mention.

Notes on what was decided rather than merely fixed:

* **A6 took the re-entrant reading.** The sketch offered "reset the cursor per
  frame, or raise on a second call". A listener awaiting `next_()` twice *is* a
  retry, and the rest of the chain running twice is what that means — so
  `waterfall` recursed per frame instead. It also removed the shared `state`
  list, so a replacement handed down no longer outlives the call that passed it.
* **A9 is a gap, not a design, and is written down as one.** An `isolate:` row
  mounts at `realm.plugin(...)`, so `reaches` finds its listeners an ancestor of
  no dispatch target: it keeps its private `ctx.fs` and silently stops hearing
  every event it registered for. The two halves pull against each other — the
  realm is what makes the service lookup private and the same property makes the
  listeners invisible — so DESIGN.md §2.7 now states the limit and
  `test_an_isolating_rows_listeners_hear_only_the_realm` pins the behavior. Making
  realm hooks `global_` is the likely answer and is a change to what isolation
  means; nothing ships with `isolate:` yet.
* **A13 refuses a second *owner*, not a second declaration.** The no-op for an
  identical re-declaration stays — a module imported under two paths is ordinary.
* **C10's binding had to go around the `await`, not the `__anext__()`.** The
  first attempt at the fix reproduced the bug one level down: building the
  coroutine runs none of the generator. The behavioural test caught it, which is
  what it was written for.
* **I1 was already resolved** by the increment that bumped the guest to 2; what
  landed is the guard that keeps DESIGN.md and `ph_runtime.protocol` from
  drifting again.
* **K9 is checked at the identity, not at each store.** A session id names a
  directory in the spill store, the archive and the workspace scratch root, and
  each sanitizes the *other* half of the name. It is also a key — `_entries`,
  `parentSession`, the roster — so sanitizing per store would map two ids onto
  one directory. `SESSION_ID_INVALID` joins the closed `ForkRejection` set.
* **K10 bounds the stall rather than removing it.** `record` is synchronous and
  every caller reaches it from the event loop, so five seconds of lock wait is
  five seconds the daemon serves nothing. A quarter second is far past what the
  critical section costs. Doing it off the loop needs `record` and its four
  callers to become async, which is a follow-up rather than something to smuggle
  into a bug-fix increment.
* **X3 sweeps only a full walk.** `paths`/`glob` narrow it, and what a narrowed
  walk did not visit is "not asked for" rather than "deleted" — a guard rail with
  its own test in both packages.
* **D13 changed a test that encoded the defect.** `test_a_procedure_that_grew_…`
  asserted a newly appended step "waits on nothing it did not arrive with", which
  was the chain being built over what is *missing* rather than over what the
  skill declared.

**D10 landed, and the premise was the part to give up.** The deferral stood on
"acting on it means returning content for a value-bearing accept, which
`finalize` refuses" — true, and the refusal was the defect. `value` and `content`
are two *consumers*: the program receives the first (`bridge.call` hands it to
the cell) and the model reads the second. Under Code Mode the program already
holds the object in a variable, so the context cost was never the value, only the
render that lands in the transcript. One rule covers both transports — **spill
the render, pass the value through** — because under native tool calling nothing
reads the value at all.

Three changes. `Accept` may carry a replaced value *and* a replacement content,
which is the explicit statement that they differ; the old refusal was written
before any row had a legitimate reason to say so, and offload is that reason.
`ToolRuntime.projected` renders a candidate value bound as the **tool's** row, so
the measurement happens inside the binding P6-26 owns rather than at a policy row
holding its own `Running` — the first cut rendered inside `offload`, which is
exactly the unbound-row-code regression `test_registration_ownership.py`'s
`BOUND` table exists to prevent. And `offload` measures that projection instead
of returning early. It is not a second render: supplying content back means the
registry renders nothing.

This settles the question `docs/dev-notes/phase-3.md` recorded and
`test_governance_gate.py` carried in its docstring — *"a generic policy cannot
invent a replacement value without knowing the tool"*. It never had to.

**And a spilled result is now searchable, which it already was.** Investigating
the follow-up found two claims wrong, both worth recording because the wrong ones
were the expensive ones. Agents are **not** limited to relative paths — `named()`
*reports* relative inside the workspace for prefix-cache stability (A11/A12),
`resolve` passes an absolute path through, and the shipped rule set restricts
writes only; `read`, `grep` and `glob` all reach `$PH_HOME/spill` today, verified
against a real `FsService`. And spills are **not** collected while referenced:
`sweep_session` drops what a log "no longer names", and an `offload/spilled`
event names its locator for the life of that log — it even *reports* a named blob
that has gone missing rather than staying quiet.

So neither a path exception nor an in-repo spill directory was needed. Three
smaller things were:

* `SPILL_TOOLS_HINT`, appended after the upstream replacement rather than folded
  into it — the verbatim block describes paging as the only way through, and
  names `read_file`, which is not a tool pH has. Appending keeps the next
  upstream comparison honest.
* `permissions-fs` treats the spill root as *inside* for a **read**. This changes
  no shipped behavior — nothing restricts reads today — and that is the point: a
  deployment adding `deny read outside-workspace` was breaking every retrieval
  hint in every session, silently, with no way to see why. Writes stay outside,
  because an agent that could write there could forge a blob under a locator the
  log already names.
* `text_index` covers a spill when asked for it by path. Deliberately not in the
  default walk: embedding every spilled result of every session unasked is
  minutes of model time for output nobody has searched. The X3 sweep composes
  with it *because* it asks the filesystem — the argument-shape version this
  increment replaced would have forgotten every indexed spill at the next
  ordinary `text_index .`, which now has a test of its own.

**A `/simplify` pass then moved six of these deeper, two of them because the
first cut was wrong:**

* **X3 was deciding by argument shape and had two live index-emptying holes.**
  `sweeping = args.paths == ["."] and …` tests the *spelling of the request*,
  not the *coverage of the walk* — and `fs.collect` stops at `max_files`
  reporting nothing, while the `permissions-fs` screen prunes directories. On a
  tree past the cap, or with a rule hiding a subtree, `paths` is a subset and the
  sweep forgets everything it did not reach. Both sweeps now ask the filesystem
  (`exists()`), which is the only thing that means "deleted" and is correct for
  narrowed, truncated and pruned walks alike. The `sweeping` flag, and its
  duplicate in two packages, are gone.
* **K9's guard sat downstream of the traversal it prevents.** `open_session`
  builds three paths from the raw id before `SessionStore` sees it: `claim`
  creates `<root>/.leases/<id>.lock`, `exists` locates the log, and
  `resume_session` *opens and parses* it — then calls `adopt`. The check moved to
  the first statement of that door and to `SessionParams`, the wire type every
  `session/*` method on both transports takes.
* **C9's third `except` was still missing three cases.** `BaseExceptionGroup`
  (which is how an anyio task group delivers a cancellation), `KeyboardInterrupt`
  and `SystemExit` all still recorded `completed`. `ends is None` can only mean
  "an exception left the body" — every normal exit assigns first — so
  `_turn_reason` derives `aborted` from that and the branch is deleted. Fewer
  lines, and correct for exceptions not yet invented.
* **A8 became identity removal rather than `eq=False`.** `_registry.claim_entry`
  already documents this exact bug as "this module's whole complaint one
  container over" — this is that container — and matching its shape avoids
  silently changing what equality and hashing mean for `Hook`. `_Effect` was
  checked and is safe by accident: `release` marks `done`/`ran` *before* the
  `remove`, which disambiguates the twin; that is now written down where somebody
  would wonder.
* **D11's empty-string sentinel became a question.** `""` meant both "no literal
  head, could be anywhere" and "the workspace root, contains everything" — nearly
  opposite claims told apart only by the order of two guards. `_could_match_under`
  takes `at_root` and `require_head`, `_under` is total path containment again,
  and `_has_head` is gone.
* **X4's trim moved into `_tail` as a budget.** The caller's loop and `_tail`
  were two owners of one decision counting width differently (raw `len` against
  `len + 2` separators).

Also: `_first_object`'s 24-line brace scanner became `json.JSONDecoder.raw_decode`

reply eagerly at 32 ns/char for a candidate usually thrown away. The glob
alphabet moved to `fs.literal_head` beside `matches_glob`, cached, which makes
the permission screen *faster* than before the dialect was fixed (6.5 µs against
8.8 µs per directory). `insert:`'s duplicate-id refusal is gone in favour of the

**Declined, with reasons:** spelling `_normalized`'s per-chunk binding as
`_ACTIVATING.set/reset` the way `_invoke` does — that one is inside cordis and
may touch its own ContextVar, and reaching for it from `ph.llm` is a private

**Also fixed here: a macOS-only CI failure in
`test_a_cell_blocked_behind_a_large_reply_is_still_killed`.** Not one of the 31
— found by CI while this increment was open, and in `ph_rlm.kernel.manager`,
which increment 9 had not touched. The socket has *three* ways of saying it has
been closed underneath a caller and the module caught two: `send`/`recv` raise
`OSError`, `notify_closing` raises `ClosedResourceError` into a waiter already
parked, and `wait_readable`/`wait_writable` **entered** with a closed socket
raise `ValueError("Invalid file descriptor: -1")`, because `close()` sets the
fileno to `-1`. The third is a loop *re-entry*, which is why a partial write
finds it: an 8 MB reply goes round `wait_writable`/`send` many times and the stop
ladder's teardown lands between two turns. Linux passed because which of the
three arrives first is a matter of buffer sizes and wakeup order. Both waits now
share one `_CHANNEL_GONE` tuple, and the shape is pinned deterministically rather
than left to a race that reproduces on one platform.

Each is a small change with a small test; none blocks the others. The two worth
deciding rather than fixing are A6 (either support re-entry by resetting the cursor
per `next_` frame, or raise on a second call so the footgun is loud) and A9 (state
in `DESIGN.md` §2.7 whether an isolating row is meant to hear root events).
